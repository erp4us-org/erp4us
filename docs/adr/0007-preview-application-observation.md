# ADR 0007: Read-only application observation for the local preview

**Status:** draft for integration review; no production runtime trust decision. See [#122](https://github.com/erp4us-org/erp4us/issues/122).

**Context.** Operators need to distinguish application readiness from container state. The existing HTTP readiness endpoints check more than the Docker process. Direct access to a Docker socket, including a read-only filesystem mount, does not satisfy the least-privilege requirement.

**First adapter.** The diagnostics service checks fixed targets concurrently with deadlines: the Master Data and Manufacturing HTTP readiness endpoints and the native JetStream account API. The HTTP probe differentiates an error status from an unreachable target. A dedicated broker credential can query only account info, the named preview business stream, `article-receipts`, `inventory-sales-v1`, `procurement-material-plans-v1`, and the Article Relay heartbeat interval. It can subscribe only to its reply inbox and the exact Article Relay heartbeat subject, never fetch JetStream deliveries or modify resources. The reporting API returns readiness, observation time, selected counters and heartbeat status; absent measurements are null, not zero. The heartbeat age uses local monotonic receipt time and is invalidated on broker disconnect. Origins, paths and broker resources are not caller-controlled, and upstream bodies and credentials are never forwarded. The endpoint uses an explicit platform grant on the verified principal, independent of any tenant/organization role. The workspace polls this read-only report; it does not infer process state or attempt to restart anything.

**Consequences.** No new Docker permission or cross-context database access is granted. The service can detect a stopped application, but cannot distinguish a missing container from a network outage using HTTP alone. Runtime inventory, resource usage and redacted logs require a separate constrained collector design and review. An eventual Kubernetes adapter should supply runtime observations without changing this application status contract. No existing payloads or persisted data migrate.
